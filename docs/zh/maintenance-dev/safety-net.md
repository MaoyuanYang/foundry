# maintenance-dev —— 安全网与验证

把"行为保持"从一句主张变成可验证论断的证据纪律。

## 什么算可观察行为

API 请求/响应契约与状态码、CLI 输出与退出码、UI 状态与文案、事件与消息载荷、持久化数据形状与完整性规则、文档化的时序保证、配置语义。内部命名、模块布局、去重、实现策略**不是**可观察行为——它们恰恰是重构可以改变的东西。

## 基线快照

任何切片之前，为战役触及的每个表面记录基线：

| 表面 | 基线证据 | 类型 |
|---|---|---|
| `<API / CLI / UI 流程 / 数据 / 事件>` | `<命令 + 输出、契约探测结果、内容哈希或记录的交互>` | `<Runtime / Tests / Contract / Hash>` |

优先可执行证据：运行项目的验证命令，记录精确命令、环境、版本、`commit/ref` 和结果。测试覆盖不到的行为，捕获一个特性化探测（characterization probe），标注 `OBSERVED` 及捕获条件。**完全无法捕获或测试的行为表面会阻塞 `SAFETY NET READY`**——记录缺口并 `STOP`；绝不盲切。

## 特性化测试

覆盖不足处，在改动表面**之前**补特性化测试：

- 记录的是当前行为——包括怪癖——而不是期望行为。
- 通过公共接缝（API 边界、CLI、渲染出的 UI、事件流）测试，不测内部函数。
- 发现某个怪癖其实是缺陷时，不在 `REFACTOR`/`DEBT` 切片里修：记为候选 `feature-dev` Bug，特性化测试继续断言当前行为，让修复作为独立的行为变更工作项运行。

## `SAFETY NET READY`

10 项清单全部满足才 PASS：每个触及表面已枚举并有基线证据；既有验证命令已在战役前运行并记录；覆盖不足处已记录特性化测试；没有盲切；逐切片回归范围已记录；基线证据有标签且可复现；并发认领已检查；`UPGRADE` 专项清单（版本、lockfile 策略、破坏性变更）；`RETIRE` 专项计划（见[弃用与移除](./deprecation)）；门禁记录含清单、验证时间与权限批准。

**本门禁 `PASS` 之前不得运行任何实现切片。**

## `BEHAVIOR PRESERVED`

逐切片：运行该切片的回归范围，对其表面重跑基线探测并比对。任何差异都要分类——`defect`（切片内修复）、`unintended change`（回退或收窄切片）、`intended change`（停止切片；带着具名 Decision Authority 走 Design Change 和 `feature-dev`）。没有记录证据的切片不算已验证。

战役级：在最终状态上运行完整回归范围并对所有触及表面做最终基线比对，合并前的集成重跑之后再次执行。任何切片在验证后发生变化、或范围/安全网发生语义变化时，门禁转 `STALE`。
